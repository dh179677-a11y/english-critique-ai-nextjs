# 绘本精讲语言知识流程设计

## 目标

将绘本精讲从“带读、跟读和发音训练”调整为原文驱动的语言知识课，重点讲解语境词义、语法、重点句型和实际应用，并降低无效互动频率。

## 独立精讲流程

首次进入精讲时固定使用简洁开场：

> 我们开始绘本精讲。今天重点学习原文里的单词、语法和句型应用。我会结合画面讲清楚用法。现在先听我讲当前页。

开场中“重点”只出现一次，不说“不要求学生跟读”，具体教学限制由内部提示控制，不直接念给学生。

每个可见跨页按以下顺序进行：

1. Mia 自然朗读当前原文一次，用于呈现内容，不要求学生跟读或复述。
2. 讲解重点单词：结合原文句子、当前画面和故事情境说明准确含义、词性、常见搭配和本课用法，再给一个贴近儿童生活的短例句。
3. 仔细讲解重点句：拆解句子结构和核心语法，说明为什么这样表达、哪些部分可以替换应用，并给一个同结构例句。
4. 左右页全部讲完后最多提出一个问题。
5. 学生回答后给予简短、针对性的反馈，再提示翻页继续。
6. 整本书结束时只总结重点单词、语法、句型和应用，不评价发音、语调或朗读流畅度。

## 语境释义规则

- 单词含义必须由当前英文原文、当前画面和故事情境共同确定，不能机械使用最常见的字典释义。
- 先解释“这个词在当前绘本里的意思”，必要时再简短补充其他常见含义，不能反过来。
- 画面用于帮助确定原文词义和动作关系，不用于让学生自由描述图片。
- 如果画面和原文不足以确定具体含义，应明确使用保守表达，不得凭绘本记忆或旧页面补全。
- 强制示例：在生病、皮肤出现红点的故事情境里，`spots` 应解释为“皮肤上的红疹、疹子或红点”，不能只解释为普通“斑点”。

## 问题规则

- 每个跨页最多一个问题，左右页全部讲完后再问。
- 问题必须直接对应当前英文原文，可考查：
  - 当前语境中的词义；
  - 句子结构或语法选择；
  - 用重点句型替换一个词完成新句子；
  - 对原文明确表达内容的理解。
- 禁止让学生描述画面、自由编故事、预测剧情或回答与原文无关的问题。
- 禁止用问题变相要求学生跟读、重复朗读或练习发音。

## 移除的旧流程

- 第二轮学生自主朗读。
- 发音准确度、语调、流畅度和完整度反馈。
- 跟读、反复重读和发音训练。
- “你看到了什么”等泛化画面描述问题。
- 每侧页一个问题的高频互动。

## 架构

为 Storyflow 绘本精讲建立独立的学习流程提示和精简状态，不再注入通用的两轮 `agentLessonFlowPrompt`。看图说话、影子跟读和独立 Agent 页面继续使用原有流程，避免本次调整改变其他模式。

精讲状态只覆盖开场、当前跨页语言讲解、原文问题、翻页和总结。页面变更仍通知现有 RTC 智能体，不新建额外语音链路。

## 验证

- 结构测试确认精讲不再注入第二轮朗读与发音反馈规则。
- 结构测试确认每个跨页最多一个原文问题，并禁止图片描述问题。
- 结构测试确认词义由原文、画面和故事情境共同决定。
- 加入 `spots` 在生病情境中解释为红疹/疹子的回归断言。
- 运行全部 Storyflow 检查、ESLint 和 Next.js 生产构建。

## 非目标

- 不修改影子跟读和看图说话流程。
- 不修改语音识别、字幕合并、评分或录音功能。
- 不预生成或持久化整本书固定教案。
