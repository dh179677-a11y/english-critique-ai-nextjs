# 绘本精讲左右页原文设计

## 目标

绘本精讲模式遇到包含 `[RIGHT_PAGE]` 分隔符的跨页原文时，不再把分隔符作为正文显示，而是像影子跟读一样，将正文分别展示为 `LEFT PAGE` 和 `RIGHT PAGE` 两张卡片。

## 范围

- 仅调整学生端绘本精讲页面的原文展示区域。
- 复用现有 `splitDualPageText()` 解析逻辑，不改变后台数据结构、OCR 内容或语音流程。
- 不修改影子跟读页面现有行为。

## 展示规则

1. 当前页同时存在左页和右页文本时：
   - iPad 和桌面宽度使用左右双栏。
   - 左栏标题为 `LEFT PAGE`，使用天蓝色强调样式。
   - 右栏标题为 `RIGHT PAGE`，使用靛紫色强调样式。
   - 正文完整显示，不出现 `[RIGHT_PAGE]` 标记。
2. 当前页只有单页文本时：
   - 保留现有单栏 `PAGE TEXT` 展示。
3. 小屏幕宽度不足时：
   - 两张卡片上下排列，避免文字拥挤或溢出。
4. 当前页没有后台原文时：
   - 保留现有缺省提示文案。

## 实现方式

在 `StoryflowTaskPlayer` 当前页数据派生区域计算精讲原文的左右页部分。精讲原文区域根据是否存在右页文本选择双栏或单栏渲染。样式沿用影子跟读的左右页颜色和卡片结构，但不增加音频点击、焦点或录音交互。

## 验证

- 添加结构回归测试，确认精讲原文调用 `splitDualPageText()`。
- 添加渲染结构断言，确认双页分支包含 `Left Page` 和 `Right Page`，单页分支仍包含 `Page Text`。
- 运行全部 Storyflow 检查、ESLint 和 Next.js 生产构建。
- 在本地浏览器验证双页内容、单页回退和响应式排列，并检查控制台错误。

## 非目标

- 不重新生成或清洗现有绘本文本。
- 不改变页面翻页逻辑。
- 不改变 Mia 的提示词、字幕或语音识别行为。
