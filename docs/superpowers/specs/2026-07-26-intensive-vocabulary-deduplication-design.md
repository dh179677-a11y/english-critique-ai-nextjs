# 绘本精读已讲词汇去重设计

## 目标

绘本精读实时语音讲解中，同一词族在本次绘本的前页已经完成精细讲解后，后续页面再次出现时不得重复讲解词义、词性、搭配和生活例句。

例如封面已经精讲 `children`，内页出现 `Two children came.` 时，Mia 最多简短提醒“children 就是前面讲过的孩子们”，随后直接讲当前句子的新增语言知识。

## 范围

本设计仅修改“绘本精讲”实时语音模式，不改变看图说话、影子跟读、口语测评或绘本数据结构。

去重记忆以当前绘本和当前页面顺序为边界：

- 当前页之前首次出现的重点词视为已经完成精讲。
- 当前页第一次出现的重点词可以完整讲解。
- 断线重连、RTC 会话重建和翻页提示都必须重新携带已讲词族清单。
- 整本书总结可以汇总已学词汇，但不得重新逐个做完整精讲。

## 词族识别

程序把重点词汇归一化为词族键，比较时忽略大小写、首尾标点和常见词形变化。

必须覆盖以下示例：

```text
spot / spots -> spot
come / came -> come
child / children -> child
```

规则优先处理常见不规则词，再处理安全的复数和常见动词后缀。归一化必须保守，不能为了合并词族而把无关单词误判为同一个词。

`the`、`and`、`is`、`on`、`they` 等高频功能词，以及分页标记产生的 `right`，不进入“已精讲重点词”清单。过滤清单只服务于精讲去重，不修改页面原文或后台 `keyVocabulary`。

## 已讲词汇来源

使用当前绘本分析结果中当前页之前各页的 `keyVocabulary`，不依赖实时字幕。

选择这一来源的原因：

- 精讲流程要求每页覆盖重点单词，因此顺序完成前页后，可以稳定视为已讲。
- RTC 字幕可能缺失或误识别，无法可靠区分“自然朗读”与“详细解释”。
- 页面数据在翻页和重连时始终可用，可重复生成相同结果。

如果前页没有 `keyVocabulary`，不从普通原文的所有单词中推断已讲词汇，避免把只是朗读过的词错误标为已经精讲。

## 提示词行为

共享精讲提示加入全局规则：

1. 已讲词族再次出现时，只允许一句简短回顾。
2. 禁止重复词性、完整词义列表、常见搭配、发音拆解和生活例句。
3. 当前句子有新的语境含义时，可以说明“这一次在句子里表示什么”，但不能重新展开整套词汇讲解。
4. 当前页优先讲第一次出现的新重点词、一个有用的语言规律和整句应用。

页面上下文加入机器生成区块：

```text
【本次绘本此前已经精讲的词族】
child（此前形式：children）
come（此前形式：came）
```

没有已讲词族时，明确说明当前尚无历史精讲词汇，避免模型从旧会话或其他绘本自行推断。

该区块必须进入：

- RTC 初始课程状态提示；
- 翻页后的静默上下文同步；
- 翻页后触发继续讲解的控制消息；
- 断线重连后继续当前页的提示。

## 组件边界

`lib/agentLessonFlow.ts` 负责纯函数：

- 归一化单词为词族键；
- 过滤非重点功能词；
- 从当前页之前的 `keyVocabulary` 构建去重后的已讲词族记录；
- 格式化 RTC 提示区块。

`components/student/StoryflowTaskPlayer.tsx` 只负责提供页面列表和当前页索引，并把生成的提示区块加入现有 RTC 上下文。组件不自行复制词形规则。

## 错误与降级

- 页面或 `keyVocabulary` 缺失时返回空清单，精讲仍正常运行。
- 无法识别的词保持其清理后的原形，不做激进词干截断。
- 已讲词清单设置合理上限，防止长绘本提示无限增长；优先保留最近且与当前页面重复的词族。
- 去重辅助信息不得覆盖“当前页可信原文是唯一语言依据”的现有安全规则。

## 测试

结构和纯函数测试必须验证：

1. `spots` 与 `spot` 合并。
2. `came` 与 `come` 合并。
3. `children` 与 `child` 合并。
4. 大小写和标点不影响匹配。
5. 功能词和 `right` 被过滤。
6. 只读取当前页之前的 `keyVocabulary`。
7. 重复词族只保留一条，并保留此前出现形式用于提示。
8. RTC 初始、翻页和重连提示都包含已讲词汇区块与禁止重复精讲规则。
9. 现有绘本精讲、RTC 语音和生产构建检查继续通过。

## 不在本次范围内

- 跨绘本、跨学生或跨登录会话记忆词汇。
- 把已讲词汇写入服务器 JSON。
- 根据 ASR 字幕判断讲解完成度。
- 修改老师端绘本分析生成的 `keyVocabulary`。
